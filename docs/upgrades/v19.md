# Upgrade to Umbraco 19

From `18.x` (floor `18.0.0`, compared against `release-18.3.1`) to `19.0.0-beta1` (tag
`release-19.0.0-beta1`). Branch `v19/topic/cms-19-upgrade`, cut from `v19/dev` (itself cut from
`v18/dev` at `6ec12f10f` on 05-11-2026).

**Targets CMS release:** `release-19.0.0-beta1`. While this is a pre-release, every product's
own version is a pre-release too (`19.0.0-beta.1`, dotted, per CLAUDE.md). `19.0.0-rc1` is
already on MyGet and npm but has no GitHub release yet; refresh to it when it ships.

**Scope:** 26 products. Umbraco.AI.Deploy, Umbraco.AI.Prompt.Deploy and Umbraco.AI.Agent.Deploy
joined on 11-11-2026, on Umbraco.Deploy `19.0.0-beta1` (see "Umbraco Deploy 19"). Umbraco.AI.Automate
stays on 18 for now (see Blockers).

### Umbraco Deploy 19 (added 11-11-2026)

Umbraco.Deploy `19.0.0-beta1` is on the MyGet prerelease feed (11-11-2026). Compared with
18.0.1 by decompiling both `Umbraco.Deploy.Core` and `Umbraco.Deploy.Infrastructure` (no public

- **`IDiskEntityService.RegisterDiskEntityType` removed** (breaks the build)\

  Hits: `UmbracoAIDeployComponent`, `UmbracoAIPromptDeployComponent`,
  `UmbracoAIAgentDeployComponent` (their constructors took `IDiskEntityService` only for this)

  `SuspendDatabase`/`ResumeDatabase` (not called) and gains `GetSignature`/`GetSignatures`;
  `IServiceConnectorFactory` gains `TryGetConnector`; `IDiskEntityService` gains
  `BeginDiskReadAsync`. Deploy's own saved/deleted refresher bases are unchanged, so our
  handlers keep the same pattern. No `CS0618` from Deploy.
- **Deploy needs `Umbraco.Licenses` `[19.0.0-beta, 20.0.0)`**, published only on the MyGet
  prerelease feed. Hits: `NuGet.config` source mapping.
- **Deploy 19 checks its licence before a trigger file runs**, but lets a not-yet-validated
  licence through while the site starts. On an unlicensed local site, `deploy` while running
  fails "license check failed with status: Pending"; `deploy-on-start` works. Testing only.
- **Framework and markers**: net11.0 (`Directory.Build.props` and each csproj), `version.json`

## Decisions

- 05-11-2026: Analytics.UI design (issue #38): hourly bars in `uaui-time-series-chart` for whole-day
  ranges of 2 days or less, `uaui-group-by` gains `hour`, points carry local `YYYY-MM-DDTHH:00`,
  chart `today` renamed `now`, new `today`/`yesterday` presets (opt-in). No rolling 24 hours.
  Our overview endpoint's hourly cap drops to 2 days to match; the dashboard offers Today,
  Yesterday and two-day ranges hourly.
- 05-11-2026: Task 14 (dashboard) waits for the Analytics.UI release with hour slots; tasks
  15-18 go first. The overview endpoint keeps its `Hour` granularity.
- ~~05-11-2026: Hourly usage drawn with Analytics.UI's category chart.~~ Replaced the same day:
  the library is adding hour slots to the time-series chart instead (decision above).
- 05-11-2026: Deploy x3 and Automate left out until their v19 packages ship.
- 05-11-2026: Branch model: `v19/dev` and `v19/main` cut from `v18/dev`; the upgrade lands by
  PR into `v19/dev`.
- 05-11-2026: Analytics dashboard moves to Umbraco.Analytics.UI as part of v19.
- 05-11-2026: Third-party picks: Anthropic 13 and @ag-ui/client 1.0, both in.
- 05-11-2026: Remove the 13 members marked "Will be removed in v3" on `IAIChatService`,
  `IAIEmbeddingService`, `IAISpeechToTextService`. Marked in Umbraco.AI 1.7.0 (0a134ce44,
  17-03-2026), before versions aligned with the CMS; 17 and 18 have shipped since, which meets
  the "current + 2" rule.
- ~~05-11-2026: Usage dashboard drops the "Last 24 hours" hourly view for now.~~ Replaced the same
  day after umbraco/Umbraco.Analytics.UI#38 (hourly via the time-series chart, above).
- 05-11-2026: `initialized` and collectionView `pathName` can't move on 18. `part()` only waits
  for init from 18.2.0 (`release-18.2.0` `UmbConfigRepositoryBase`), and `pathName` still routes
  views on 18.0/18.1. `initialized` moves to task 10 (19 removes it); `pathName` stays (still a
  required field at `release-19.0.0-beta1`, removal in 20).
- 05-11-2026: `SearchUmbracoTool` on CMS 19 core search keeps v18's behavior where it can:
  member-protected pages stay out (null access context, as v18's `ExternalIndex` had
  `supportProtectedContent: false`); candidates are capped and enrichment stops at
  `maxResults`. The CMS searcher matches all words (`Searcher.CreateBaseQuery`), v18 matched
  any; the tool now tries all words first, then falls back to per-word searches, and its
  description asks the LLM for short keyword queries.
- 05-11-2026: ImageSharp 4 decodes opaque RGB PNGs as `Rgba32`, so `AIImageEncoder.HasAlpha`
  now scans pixels (stops at the first non-opaque one). A fully opaque RGBA PNG is now
  re-encoded as JPEG, where it stayed PNG before.
- 05-11-2026: Prompt scope rules naming a pre-19 UI alias keep matching the data types the CMS
  migration moved (old alias also matches its v19 split), rather than migrating stored rules.
  No data rewrite, and a rule saved on 18 means the same thing on 19.
- 05-11-2026: Single media/URL picker handlers reject a second `add_item` (the CMS schema says

## Breaking changes for consumers

- .NET 11 and CMS 19 only.
- Umbraco.AI.Deploy, Umbraco.AI.Prompt.Deploy and Umbraco.AI.Agent.Deploy need Umbraco.Deploy 19.
  `UmbracoAIDeployComponent`, `UmbracoAIPromptDeployComponent` and `UmbracoAIAgentDeployComponent`
  lose their `IDiskEntityService` constructor parameter: Deploy 19 removed the method they used
  it for, so there is nothing to proxy to. Disk entity types are now registered by the composers
  through `DeployEntityTypesOptions`.
- `SearchUmbracoTool` constructors no longer take `IExamineManager`; ranking and word matching
  now come from CMS core search, so results differ from v18.
- ImageSharp 4.
- Usage analytics GET endpoints obsolete (removal in v20). Use `usage-overview` in place of
  `usage-summary` and `usage-time-series`, and `usage-breakdown` in place of the four
  `usage-by-*` endpoints.
- Removed: `AISerializedProperty` (obsolete and unused since 1.2.0; entity data lives in
  `AISerializedEntity.Data`).
- Removed: the 13 members marked "Will be removed in v3". Use the builder overload that replaces
  each one; its first argument is an `Action<Builder> configure` (`.WithAlias(...)`, optional
  `.WithProfile(...)`, `.WithChatOptions` / `.WithEmbeddingOptions` / `.WithSpeechToTextOptions`).
  `WithAlias` is required (the builder throws without it). The old methods logged under a fixed
  alias (`"chat"`, `"embedding"`, `"speech-to-text"`); pass the same alias to keep log and audit
  names unchanged:
  - `IAIChatService`: `GetChatResponseAsync(messages, options)` and
    `GetChatResponseAsync(profileId, messages, options)` → `GetChatResponseAsync(configure, messages)`;
    `GetStreamingChatResponseAsync` (2 overloads) → `StreamChatResponseAsync(configure, messages)`;
    `GetChatClientAsync(profileId)` → `CreateChatClientAsync(configure)`.
  - `IAIEmbeddingService`: `GenerateEmbeddingAsync` (2 overloads) →
    `GenerateEmbeddingAsync(configure, value)`; `GenerateEmbeddingsAsync` (2 overloads) →
    `GenerateEmbeddingsAsync(configure, values)`; `GetEmbeddingGeneratorAsync(profileId)` →
    `CreateEmbeddingGeneratorAsync(configure)`.
  - `IAISpeechToTextService`: `TranscribeAsync(audioStream, options)` and
    `TranscribeAsync(profileId, audioStream, options)` → `TranscribeAsync(configure, audioStream)`;
    `GetSpeechToTextClientAsync(profileId)` → `CreateSpeechToTextClientAsync(configure)`.
- Image inputs: a fully opaque RGBA PNG is now re-encoded as JPEG before it is sent, where it
  stayed PNG on 18 (see Decisions, 05-11-2026).
- Anthropic SDK 13 (consumers referencing it directly).
- Anthropic: temperature, top_p and top_k are now ignored for every Claude model, because API
  version 2026-10-21 removed them. Profiles that set a temperature keep saving it, but it no
  longer reaches the request, and the editor hides those fields for Anthropic models.
- Agent frontend (`@umbraco-ai/agent`) moves to @ag-ui/client and @ag-ui/core 1.x. This changes
  some exported types and one behaviour:
  - Approval resume entries now travel in `RunAgentInput.resume`, not `forwardedProps.resume`.
    `UaiHttpAgent` no longer moves `forwardedProps.resume` into the request, so a custom
    `AgentTransport`, or code that calls `UaiHttpAgent.run` directly, must set `input.resume`.
    If it doesn't, approvals never resume and the user is asked again.
  - `EventType` no longer has `THINKING_START`, `THINKING_END` or `THINKING_TEXT_MESSAGE_*`. It
    gains `SUBAGENT_*`.
  - `ToolMessage.content` and `ToolCallResultEvent.content` are now `string | ContentPart[]`.
  - `RunFinishedOutcome` has a new `cancelled` variant.
  - `AgentTransport.run` takes the 1.x `RunAgentInput`.
  - `zod` is now a declared dependency (a required peer of @ag-ui/client 1.x).
